# 設計ドキュメント

この基板の設計で決めたことと、その理由、レビューでの指摘と対応をまとめます。

- 回路の考え方、タイミングの計算、測定の結果は、作者の別リポジトリ [`m5stack_board_unitree_servo_bench`](https://github.com/kim-xps12/m5stack_board_unitree_servo_bench) にある設計メモ [`atoms3r/docs/ttl_board_redesign.md`](https://github.com/kim-xps12/m5stack_board_unitree_servo_bench/blob/main/atoms3r/docs/ttl_board_redesign.md) に詳しく書いてあります (§6 回路、§6.3 タイミング、§6.7 KiCad での実装、§6.8 JLCPCB)。
- この基板は DYNAMIXEL 用の基板 (<https://github.com/kim-xps12/m5stack_board_dynamixel_ttl_rs3485>) を複製し、回路を作り直したものです。

## 2. 回路

- **送信の自動切り替え**: D1 (RB751V-40)、R1 (68 kΩ)、C6 (100 pF C0G)、U1 (74LVC1G14)。
  - TX が Low になると、D1 が RC ノードを引き下げ、TXEN が High になる。
  - TX が High の間は R1 × C6 で充電され、TXEN が Low に戻る。
  - 送信の保持時間は 3.3〜7.3 µs。パケット内の High の最長 2.25 µs より長く、サーボの応答開始 (約 21 µs) より短い。
  - R1・C6・D1・U1 を変えるときは、設計メモ §6.3 で計算し直す。C6 は温度で値が変わりにくい C0G、D1 はリークの小さいショットキー。
- **バス**:
  - 送信は U3 (74LVC1G126、TXEN が High の間だけ出力)、受信は U4 (74LVC1G125、TXEN が High の間は出力オフ)。
  - R2 (47 Ω) は直列の保護、R3 (10 kΩ) はアイドル時に 3.3 V へ引き上げる。
  - R4 (470 Ω) は 3.3 V レールのブリーダ。サーボの信号は 5 V 系 (ユーザ確認) なので、サーボ側の 5 V へのプルアップから R3 や送信中の U3 を通って 3.3 V に流れ込む電流を逃がす。LDO は電流を吸い込めないため。プルアップの値は分からないので、5 ポートすべてに 850 Ω 以上のプルアップがある場合まで吸収できる 7 mA にした (U3 の High 出力中は (5 − 3.3) V ÷ (プルアップ ÷ 5 + 47 Ω + U3 の出力抵抗 約 25 Ω))。損失は 23 mW (定格 100 mW)。設計メモ §6.4。試作基板では、S288 のプルアップは約 10.5 kΩ で、3.3 V は持ち上がらなかった (§9)。
- **TP1**: TXEN のテストパッド。ホストのベンチ測定用。

## 3. 配置と銅箔

| ルール | 理由 |
| --- | --- |
| 部品本体 (F.Fab の外形) を基板端から 2.5 mm 以上離す (今は約 3.0 mm) | JLCPCB の組立規約。Economic PCBA をエッジレールなしで発注できる |
| 取り付け穴の中心から半径 3.5 mm 以内に、両面とも GND 以外の銅を置かない | 裏面のネジ頭、ワッシャ、金属スペーサが BAT に触れないようにする |
| サーボポートは 90° 回して下辺に 6.0 mm 間隔で一列。上から signal・BAT・GND の列 | 配置が揃い、BAT と GND を太く短い直線で結べる。間隔は、端子名のシルクを左下の穴のネジ座面 (φ7 mm) の外に置ける値 |
| 端子名「Sig / BAT / GND」は J3 の左に 1 組だけ | 5 個は並列なので、1 か所で分かる |
| ベタ: GND は表面 (裏面の残りも GND)、BAT は裏面 (優先度 1)。BAT のベタの外周は GND のベタの外周に揃える | BAT の戻り電流が真上の GND を通る。細い GND の切れ端を残さない |
| ベタのクリアランス 0.5 mm、最小幅 0.25 mm。`.kicad_dru` のルールで固定 | JLCPCB のクリアランス 0.15 mm のルールだけだと、KiCad で塗り直したときにベタのクリアランスまで 0.15 mm に変わる |
| ベタや配線に 90° の入り隅や矩形の切り欠きを作らない。45° で面取りする | 電流が角に集中しないようにする。レビューで指摘された |
| J1 と F1 のパッドはゾーンに全面で接続。ポートの BAT 列 (裏面) と GND 列 (表面) は幅 2.3 mm の直線配線で結ぶ | 大電流の経路にくびれを残さない。2.3 mm は熱逃がしの輪 (外径 2.25 mm) を覆う幅 |
| F1 は J1 のすぐ左に縦向きに置く。J1 の + から上のクリップまでは表面の BAT_IN のベタ (優先度 1)、下のクリップはすぐ下のポートの BAT の帯 (裏面) へつなぐ。ホルダーの外形は C7 と J1 の間 (それぞれ 0.07 mm) に収める | 15 A までの電流が J1 → F1 → ポートとまっすぐ流れる。BAT_IN は表面だけなので、裏面の BAT のベタが下をくぐれる |
| C7 は上側 (基板端から 2.57 mm) に置き、+ は裏面の BAT のベタ (F1 の左を上がる) にビアでつなぐ。基板名のシルクは裏面へ移した | F1 を J1 のそばに置くための並べ替え。C7 はリップルだけなので細い経路でよい |
| C7 の − パッドは GND のベタにサーマルリリーフでつなぐ | サーボの電流は C7 を通らず、リップル (許容 350 mA) だけ。スポークの容量は約 6.7 A。ベタに全面でつなぐと、リフローで左右のパッドの温まり方がずれる |
| ビア (φ0.605 mm、穴 0.3 mm) は、その銅が他ネットの配線のクリアランス (0.5 mm) と、他ネットのベタの外形から 0.5 mm の範囲に入らない位置に置く。R4 の GND ビアはパッドの真下 (BAT のベタの外形から 1.0 mm) | 入ると、ベタの縁にビアの形の出っ張りができる。`tools/checks/viacheck.py` が両方を確かめる |
| 配線幅: 信号 0.25 mm、電源 0.3〜0.4 mm | |

## 4. 製造ルールとフットプリント

- **DRC のルール**: `.kicad_dru` に JLCPCB の 2 層・1 oz の推奨値 (絶対最小値ではない) を入れている。
  - スルーホールのランド幅 0.25 mm 以上、ビアは 0.075 mm 以上
  - 配線幅と間隔 0.15 mm 以上、穴と穴 0.45 mm 以上、銅と基板端 0.3 mm 以上
  - シルクは文字の高さ 1.0 mm・線幅 0.15 mm 以上、パッドとシルク 0.15 mm 以上
- **フットプリント**:
  - すべてプロジェクト内の `Library.pretty` のものを使う。KiCad 標準のフットプリントは、シルクの線幅を 0.15 mm にしたコピーを置いている (標準は 0.12 mm)。
  - J2 は ZX-HY2.0-4PZZ 用に作った。パッド 1.35 × 1.75 mm、穴 0.85 mm (JLCPCB のランドパターンと同じ穴)、ランド幅 0.25 mm。
  - PH のコピーはパッド幅を 1.25 mm に広げた (KiCad 標準の 1.2 mm ではランド幅が 0.225 mm)。
  - J1 (XT30UPB) も作ったもの。
  - F1 (`Fuseholder_Blade_Mini_XFCN_XF-508P-B-B`) は、XFCN の図面 (本体 16.0 × 6.7 × 7.35 mm、穴は 9.80 × 3.40 mm 間隔で φ1.6 mm 以上) と JLCPCB のランドパターン (パッド 2.5 mm、穴 1.8 mm、原点は本体中心) に合わせて作った。パッドはゾーンに全面で接続する。生成スクリプトは `work/fuse_fp_xf508.py`。
- **3D モデル**: J1・J2 の STEP は LCSC が EasyEDA で公開しているもの (作成者 lcsc)。再配布してよいか確認できていないので git に入れない。取得手順は README。
  - J2 のオフセットは (0, −0.35, −0.3) mm。STEP の原点が本体中心で、0.3 mm 浮いているため。
  - J1 のオフセットは (+2.5, 0, 0) mm。
  - F1 (EasyEDA C19727305 の STEP) は原点が本体中心にあり、オフセットなしで足が穴に合う。
  - オフセットは 3D 表示と STEP 出力にだけ効き、JLCPCB に渡すファイルには含まれない。

## 5. JLCPCB の部品実装 (PCBA)

- **LCSC 番号**: 全部品の `LCSC` フィールドに JLCPCB の品番を入れている。TP1 はパッドだけなので、BOM と CPL から外す。
  - 部品を選ぶときは、JLCPCB で実装できるか (在庫、Basic / Extended、THT はウェーブはんだ対応か) を確かめる。
- **CPL の補正**: JLCPCB のランドパターン (EasyEDA) は、KiCad のフットプリントと回転の基準が違う部品がある。JST と XT30 は原点も違う。
  - `tools/jlcpcb_export.py` の `CORRECTION` は、品番ごとにランドパターンを KiCad のパッドに当てはめて求めた。
  - 当てはめは、パッドの番号ではなく機能で照合する (ダイオードはカソード、IC は 1 番ピン、コネクタは本体の向き)。D1 は Preferred Extended の C7502691 (hongjiacheng) で、JLCPCB のデータでもカソードが 1 番なので補正なし (以前の Nexperia 品 C553814 はアノードが 1 番で +180° だった)。
  - 照合の結果、パッド中心のずれは THT で 0 mm、SMD で 0.03〜0.30 mm。SMD のずれは、KiCad の手はんだ用パッドが長いことや、JLCPCB のランドパターンのパッドが外側にあること (U2 で 0.30 mm) によるもので、部品の中心は合っている (ユーザ了承済み)。回転や原点を誤るとずれはピンの間隔 (0.9 mm 以上) になるので、`tools/check_all.sh` は 0.4 mm を超えたら NG にする。
  - 外形枠 (courtyard) の中心も照合する (2026-10-12 追加)。一列のコネクタは 180° 回してもパッドの位置が重なるが、J3〜J7 のハウジングはピンの列に対して片側 1.7 mm、反対側 2.8 mm と偏っているので、逆向きなら外形枠の中心が 1.1 mm ずれる。今のずれは最大 0.05 mm (J2)。CPL の J3〜J7 だけを 180° 回すと、パッドで 4.0 mm、外形枠で 1.1 mm のずれになり、NG になることを確かめた。0.4 mm を超えたら NG。
- **Extended 部品を減らす (2026-10-12)**: Economic PCBA では Extended 部品 1 品番ごとに追加費用がかかる (Basic と Preferred Extended はかからない)。
  - D1 は同じ型番の Preferred Extended 品 (C7502691) に、U2 は DYNAMIXEL 版から流用していた AP7333-33SAG (Extended、在庫が少ない) を Basic の XC6206P332MR-G (C5446) に替えた。XC6206 はピン配置が違う (1 = GND、2 = 出力、3 = 入力) ので、回路図の記号と U2 まわりの配線を替えた。
  - U1・U3・U4 (74LVC1G は Basic と Preferred に代わりがなく、74HC は 3.3 V で遅い)、C7、コネクタは Extended のまま (計 7 品番)。
  - 品番やフットプリントを変えたら、補正を求め直し、照合をやり直す。照合に使うランドパターンは `work/jlc/` にある (git 管理外)。
- **F1**: BOM のコメントは値 (ヒューズの定格) ではなく「XF-508P-B-B fuse holder (fuse not included)」にする (`tools/jlcpcb_export.py` の `COMMENT`)。ヒューズ本体は JLCPCB では実装しない。
- **出力は `tools/jlcpcb_export.py` だけを使う**: KiCad のプラグイン (Fabrication Toolkit など) や基板ファイルの直接アップロードは、フットプリント名ごとの一律の補正しかしないので、C7 (極性)、U4 (90°)、J3〜J7 (180°) が誤る (2026-10-12 に確認)。
- **発注時**: JLCPCB の配置プレビューで向きを確かめる (D1、IC の 1 番ピン、C7 の極性、コネクタ)。JLCPCB の 3D プレビューは独自の部品モデルで描くので、J3〜J7 (C131339) のようにモデルのない部品は箱で表示される。箱は JLCPCB のフットプリントの本体の位置に描かれるので、J3〜J7 は箱の位置で向きが分かる。正しい向きなら、箱の左下に 1 番ピンの目印「[」が見え、シルクの枠は箱に隠れる。180° 逆なら箱が 1.1 mm 左にずれ、箱の右に枠「]」がはみ出し、左のラベル「Sig / BAT / GND」に箱がかかる (2026-10-12 のプレビューは正しい向きだった)。目印のシルク (逆向きの箱だけが隠す帯) を足す案は、ユーザの判断で見送った。

## 6. 回路図

- **配置**: A4 の 1 枚に、左から右へ信号の流れで並べる: Host (J2) → Auto TX enable → Bus driver / receiver → Servo ports。下の段に Servo power と Logic power を置く。
- **枠と見出し**: ブロックごとに破線の枠と見出しを付ける。
- **線とラベル**: 信号と BAT は線でつなぎ、ラベルは線に名前を付けるためにだけ使う。ラベルで飛ばして接続だけを表すと、信号の流れが読めない (レビューで指摘された)。
- **J2**: 端子を上向きに置き、+5V を上、GND を下へ長めに引き出す。ネット名 TX / RX は J2 のすぐそばに書く。
- **電源フラグ**: KiCad の ERC のためだけの電源フラグ (PWR_FLAG) は、回路から離して専用の枠 (「KiCad ERC only」) にまとめる。
- **格子と出自**: 部品と線は格子に乗せる。回路の出自 (「OpenRB-150 風」など) は回路図、README、シルクに書かない。

## 7. 図

`tools/render_images.sh` で作ります。

- 斜めの 3D は、真上から 30° 傾けた視点です。55〜60° にすると、シルクの文字が部品の陰に隠れたり読みにくくなったりします。
- 3D のレンダリングは実行ごとに少し揺れます。そのため `--readme` は、色が 20% 以上違う画素があるときだけ `docs/` の画像を上書きします。

## 8. レビューでの指摘と対応

| 指摘・問題 | 対応 | 教訓 |
| --- | --- | --- |
| サーボポートが DYNAMIXEL 版の JST EH のままだった (Unitree は PH 2.0) | B3B-PH-K-S に替えた | 流用元から来た部品、設定、ルールは、新しい対象に合うか 1 つずつ確かめる |
| ポートのピン番号を、取扱説明書の表 (① SIGNAL・② VCC・③ GND) どおりに逆に割り当てた | ユーザ提供のサーボの外形図で確認し、1 = GND に直した | ピン番号は外形図や実物で確かめる。表の番号はコネクタのピン番号とは限らない |
| 取り付け穴まわりの BAT のベタを矩形に切り欠いた | 入り隅を 45° で面取りした | ベタや配線に 90° の入り隅を作らない |
| J3〜J7 の GND にサーマルリリーフのくびれが残っていた | 配線幅を熱逃がしの輪を覆う幅にした | 大電流の経路にくびれを残さない。画像を拡大して確かめる |
| C7 のパッドのサーマルリリーフは電流的に大丈夫か | 電流の経路でないことを確かめ、そのままにした (§3) | 電流の経路と見積りで判断する |
| J2 のランド幅 0.175 mm が JLCPCB の最小 0.18 mm を下回っていた。DRC のルールが DYNAMIXEL 版の緩い値のままで検出できなかった | パッドを 1.35 mm に広げ、JLCPCB の推奨値を `.kicad_dru` に入れた | DRC のルールを製造先に合わせてから DRC を信用する |
| シルクの線が KiCad 標準の 0.12 mm だった | 0.15 mm にしたコピーをプロジェクトのライブラリに置いた | 製造先の最小値を、文字だけでなく線にも当てる |
| 部品が基板端に近く、エッジレールが必要だった | 部品本体を基板端から約 3.0 mm 離した | 発注の条件 (Economic PCBA) から配置の制約を決める |
| 回路図がラベルで飛んでいて、信号の流れが読めない | 左から右へのブロック図の描き方に描き直し、ネットリストが変わっていないことを確かめた | 回路図は人が読む図として描く。描き直したら接続が変わっていないことを確かめる |
| C6 などの GND ビアが、裏面のベタの縁に出っ張りを作っていた | ビアと配線をずらし、`tools/checks/viacheck.py` を作った | ビアの銅を他ネットのクリアランスに入れない |
| JLCPCB のクリアランスのルールが、ゾーンのクリアランスを上書きしていた | ゾーン用の 0.5 mm のルールを足し、`tools/checks/fillcheck.py` を作った | 保存済みの塗りと、塗り直した結果を比べる |
| DRC で U2 のフットプリントがライブラリと一致しないと警告された | KiCad 9 のライブラリ版に置き換えた | 警告を残さない |
| ERC で、DYNAMIXEL 版から来た線の格子ずれの警告が 17 件出た | J3〜J7 を格子に乗せて描き直した | 同上 |
| J2 の Tx / Rx の並びが M5Stack と合っているか | DYNAMIXEL 版と PORT.C の公式の表で確かめた | ピン配置は公式の資料と既存の実績の両方で確かめる |
| 斜めの 3D でシルクの文字が読みにくい | 傾きを 30° にした (§7) | 画像は、見たいものが読める角度で撮る |
| 裏面の BAT のベタの縁が F1 の BAT_IN のパッドに近く、間に残る銅 (0.2 mm) が最小幅を下回って抜け、縁に小さな欠けと突起ができていた | F1 の上だけベタの縁を上げ (帯 0.8 mm)、`tools/checks/slivercheck.py` を作った | ベタの外形の縁は、中にある他ネットのパッドからクリアランスと最小幅の合計より離す |
| F1 のクリップ (Keystone 3557、C2680614) が、JLCPCB の発注画面で在庫 0 と表示された (部品データの API では在庫あり) | 在庫の多い一体型の XFCN XF-508P-B-B (C19727305) に替えた | 部品の在庫は、発注画面の表示を正とする。1 部品で済むものを選ぶと、出力の特別扱いも要らない |
| JLCPCB のプレビューで F1 の位置と C7 の極性がおかしかった (KiCad のプラグインの出力を使っていた) | `tools/jlcpcb_export.py` の出力を使うことにした | プラグインの自動補正はフットプリント名ごとの一律の規則で、品番ごとの向きの違いを扱えない |
| BAT に保護がなく、短絡するとリポの大電流が流れ続ける | ミニ平型ヒューズ F1 を J1 の後ろに入れた (§1、§3) | 電源の入口には、短絡で電流を断つ手段を置く。部品は日本で手に入り、JLCPCB で実装できるものから選ぶ |
| 裏面で、R4 の GND ビアが BAT のベタの外形を 0.05 mm 越えていて、GND と BAT の境目がビアの形に 0.55 mm へこんでいた。`viacheck.py` は他ネットの配線しか見ておらず、見逃していた | ビアを R4 のパッドの真下へ移し (「R4」の文字は下げた)、`viacheck.py` に他ネットのベタの外形との距離を足した。直す前の基板でこのビアだけを NG にすることを確かめた | チェックを作るときは、同じ見た目の不具合を生む原因 (配線、ベタの外形、パッド) を全部挙げてから範囲を決める |

## 9. 試作基板の確認 (2026-10-21)

JLCPCB で実装した基板 (062722a) を、AtomS3R と、S288・J288 各 1 台 (どちらも 4 Mbps に設定)、サーボ電源 7.5 V で確かめた。表は S288 とベンチの結果で、J288 は表の下に書く。詳しい表と測定ログは設計メモ §7.1。

| 試験 | 結果 | 判定 |
|---|---|---|
| 4 Mbps でのやり取り 10 万回 (停止 / トルク 0 のランダムな指令) | どちらも誤り 0 | 合格 |
| 受信できる速さの範囲 (同上) | どちらも −3.03〜+0.31% が誤り 0、+0.63% で 98〜99.7% | 公式アダプタ (−2.44〜+0.63%) に上側が 0.3% 届かない。指令による差はない |
| 先頭の Low を短く / 長くしたときの応答 | −25〜+100 ns で 100% | 合格 (基準 −12.5〜+62.5 ns) |
| `sin_swing` を 4,000,000 bps で 70 秒 | 14,000 周期で取りこぼし 0 | 合格 |
| やり取り中の 3.3 V | 3.299〜3.300 V (テスター) | R4 (470 Ω) で持ち上がらない |
| ベンチ (G5 で信号線と TP1 を記録、サーボなし) | 先頭の遅れ 12.5 ns (測定の刻み 1 つ)。送信許可の保持 5.4〜5.9 µs。4 Mbps のパケットで送信許可は途中で切れない | 合格 (設計: 遅れ 20 ns 以下、保持 3.27〜7.30 µs) |
| アイドル時の信号線 | 4.13 V。サーボのプルアップは約 10.5 kΩ (5.0 V とした計算値) | 5 台でも流れ込みは 0.78 mA (計算値) で、R4 の 7.0 mA に収まる |

- 前の基板の 2 つの問題 (指令によって受信できる範囲が変わる、4 Mbps ちょうどで約半分を取りこぼす) は、どちらもなくなった。
- J288 (出荷時の 6 Mbps のまま) とも、6 Mbps (ESP32-S3 の UART の仕様 5 Mbps を超える) で誤りなくやり取りできた。ただし、この状態では `sin_swing` で動かなかった。公式ツールで 4 Mbps に設定し直したあとは、同じ 7.5 V で動いた (`sin_swing` 10 秒 + 60 秒、14,000 周期で取りこぼし 0)。4 Mbps でのやり取り 10 万回 (2 通りの指令) も誤り 0 で、受信できる速さの範囲も S288 と同じ −3.03〜+0.31% だった (誤りが出始める境目は J288 のほうが約 0.3% 遅い側)。6 Mbps の状態で動かなかった理由は切り分けていない。
